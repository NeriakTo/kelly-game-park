## 7. 已知限制

1. **測試工具版本與 lock 更新方式**：一開始裝 vitest 3.2.7，`npm audit` 因此多出 2 個嚴重、1 個中度通報（tinypool 與 `@vitest/mocker`），所以改用 4.1.12（commit `a1fd853`），通報總數回到與 `b31af4e` 相同的 12 個。本機 npm 10.9.9 更新 lock 時遇到 npm 內部錯誤（`Cannot read properties of null (reading 'edgesOut')`），改用 npm 11 更新 lock；之後用 npm 10 跑 `npm ci`、建置、測試都通過。CI 用的是 Node 22 內建的 npm 10，以 `npm ci` 讀 lock，不受影響，但這點要在 GitHub Actions 實際跑過才算確認。
2. **既有安全通報未處理**：`npm audit` 仍有 12 個（vite、react-router、postcss、rollup 等），全部是 `b31af4e` 就有的，修正要升級正式相依，不在本次範圍。
3. **主要 JS 仍偏大**：設定頁直接載入，連帶把 AI 服務程式放進主要 JS；Framer Motion 也在首頁使用。若要再降，可把設定頁也改為分開載入。
4. **數學行為的小變化**：切年級現在會把題號重設為第 1 題、答對答錯歸零（原本只歸零答對答錯，題號沿用）；若開了 AI 出題且有金鑰，切年級時也會像換單元一樣預先向 AI 要下一題。
5. **未改的過時文字**：`HANDOFF.md` 的「待處理」第 3 條（拆分載入）已完成、第 4 條（Supabase 整合）的依賴已移除；`PROJECT_PLAN.md` 仍提到 Supabase 與 2048。本次只改權杖那一行，其餘留給後續文件整理。
6. **檔案尺寸**：`MathChallengeGame.tsx` 由 497 行變 514 行，仍超過 400 行目標（規劃書 C2 已列，第二階段拆檔）。
7. **出題器的潛在無窮迴圈（未修）**：`buildOptions` 最後的補位迴圈 `options.add(answer + options.size)` 若補的數字已在集合內，集合大小不變就會一直跑。前面有 50 次隨機嘗試，實務上幾乎不會走到；本次只補測試、沒改出題器。
8. **CI 沒有跑測試**：`.github/workflows/deploy.yml` 只跑 `npm ci` 與 `npm run build`，沒有 `npm test`。本次沒改 CI（不在範圍），merge 前的測試目前要靠人工執行，或另開工作把測試加進 CI。
