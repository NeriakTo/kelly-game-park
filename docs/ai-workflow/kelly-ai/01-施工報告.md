## 與規格不同處及理由／做了哪些假設

1. **status 缺金鑰行為**：規格第三／五節要求缺金鑰時所有 AI 端點回 503，第十節又要求「不設金鑰」的冒煙 status 回 200。採第十節具體驗收：雜湊有效、通行碼正確但缺金鑰時，status 回 200、`enabled: false`；出題回 503。缺雜湊仍全部關閉。前端必須檢查 enabled，不能把 HTTP 200 當成可出題。位置 `server/src/app.ts:36`。
2. **HTTP 405 代碼**：規格只指定狀態碼，未指定 error 字串；採 `method_not_allowed`，仍維持單一 error 欄位。
3. **儲存故障**：usage.json 損壞時啟動失敗，避免靜默歸零；執行中寫檔失敗回 503 disabled 且不呼叫模型。位置 `server/src/usage.ts:12`、`server/src/app.ts:45`。
4. **紀錄路徑**：未知 API 路徑記為 `/api/unknown`，已知路徑不記 query，避免秘密被放入 URL 後進入紀錄。沒有取得上游 usage 時 token 數記 0。
5. **額度單位**：每日計數以一次 SDK 出題操作預扣一次，含操作失敗；依規格保留 SDK `maxRetries: 1`，其內部重試沒有另外扣第二次。因此每日上限不能視為實際上游 HTTP 嘗試數或帳單硬上限；主控需知悉這個語義。位置 `server/src/app.ts:45`、`server/src/model.ts:12`。
6. **測試環境**：執行期 Node v22.23.4。初次 shell here-document 因預設 TMPDIR 不可用而未寫入內容；改用 bash 與規格指定的工作目錄 TMPDIR 後恢復。首次 npm test 又繼承根設定而未找到測試；補交獨立 vitest 設定後，在尚未提交實作、移開實作目錄的狀態重新留下六組紅燈。靜態檔測試另修正為對 Buffer 轉字串後比較 HTML，沒有減少驗收要求。
